# Mac 桥接最小测试目标（2026-11-21）

## 背景

盘点文档问题 #2：`apps/mac-bridge/FairyMacBridge` 只有一个顶层代码 `main.swift`，任何函数都无法被 import，`swift test` 报 no tests found，桥接行为只能靠后端测试间接覆盖。

## 改动

- 新增库目标 `FairyMacBridgeCore`：承载全部逻辑（TCC 探测、应用列表、AX 树 BFS、Vision 图片/PDF OCR），函数改为 public，实现逐行保留。
- 可执行目标 `FairyMacBridge` 只保留命令分发与顶层错误处理，import 核心库。
- 新增测试目标 `FairyMacBridgeCoreTests`（XCTest，6 项）。
- 产物名、`.build/release/FairyMacBridge` 路径、子命令、JSON 字段与错误码全部不变；服务端 `server/fairy/mac_bridge.py` 无需任何修改。

## 测试覆盖

| # | 测试 | 验证点 |
| --- | --- | --- |
| 1 | recognizeText 不存在文件 | 抛 `ocr_image_unreadable` |
| 2 | recognizePDF 损坏文件 | 抛 `ocr_pdf_unreadable` |
| 3 | accessibilityTree 限额 | maxDepth=0 只输出根节点；maxNodes=1 截断；深度恒在 0...5；不依赖 TCC 授权，授权与否都确定性通过 |
| 4 | recognizeImage 渲染图往返 | NSImage 绘制 "FAIRY 12345"，Vision 真实识别出数字；method/line_count 字段契约 |
| 5 | recognizeText 磁盘 PNG 往返 | 覆盖 CGImageSource 文件读取路径（测试 4 只覆盖内存 CGImage） |
| 6 | recognizePDF 双页往返 + 页数上限 | CoreText 生成两页 PDF，逐页 OCR 识别 "67890"；maxPages=1 时 page_count=1 |

## 验证记录

- `swift test --package-path apps/mac-bridge/FairyMacBridge`：**6 passed, 0 failures**（首次 Vision 调用约 12 秒为模型预热，后续毫秒级）。
- `swift build -c release`：通过；随后以服务端完全相同的调用方式对 release 二进制逐项验证 CLI 契约：
  - `status`：bridge=fairy-mac-bridge、version=0.1.1、read_only=true、input_injection=false、tcc.probed=true、applications 列表（实测 55 个应用）。
  - `applications`：正常返回。
  - `ocr` / `ocr-pdf` 缺参 → `ocr_path_required` / `ocr_pdf_path_required`；不存在图片 → `ocr_image_unreadable`；未知命令 → usage；退出码均为 1。
  - `ax-tree` 在未授予辅助功能权限的进程里如实报 `accessibility_permission_required`（本机当前 shell 未授权，属预期）。
- 后端全量回归：`pytest tests -q`（真实 PostgreSQL）**180 passed**。

## 边界与剩余

- AX 树的真实内容读取需要用户在系统设置授予辅助功能（TCC）权限；本轮验证的是限额逻辑与未授权错误路径。
- OCR 往返断言使用渲染的 ASCII 数字，避免中文识别波动造成测试不稳定；zh-Hans 已配置为识别语言，但不在强断言内。
- 桥接保持只读定位：屏幕内容捕获与输入注入仍未实现，`/mac/runs` 深度执行等待用户授权与签名身份（见盘点文档「需要你做的」#3）。
