# 发布与回滚演练（账本语义）— 2026-11-21

## 目标

在隔离进化实验之上补齐「发布登记 → 替代 → 回退恢复」的完整账本链路，并做一次无人值守演练测试，验证任意时刻至多一条「当前发布」，回退能沿替代链恢复上一条发布。

## 边界（与之前一致）

发布与回退都只改变实验记录的状态，属于账本操作：

- 不部署代码、不替换评分器、不改动运行中的模型或提示词。
- 「采用候选输出」仍由所有者人工完成，页面文案持续标明「运行版本未改变」。

## 状态机

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| evaluated | 已完成隔离评测 | winner 改进时可 approve |
| approved_for_review | 待人工评审通过记录 | release、rollback |
| released | 当前发布记录（全局至多一条） | rollback |
| superseded | 被更新发布替代，等待恢复 | 无（由 rollback 自动恢复） |
| rolled_back | 已回退，终态 | 无 |

守卫：对不可发布/不可回退状态调用相应接口返回 409（`experiment_not_releasable` / `experiment_not_rollbackable`）；rolled_back 记录不能再 approve 或 release。

## 接口语义

- `POST /evolution/experiments/{id}/release`：要求 approved_for_review。把当前所有 released 记录标记为 superseded（写入 superseded_by / superseded_at），本条置为 released（released_at），发出 `evolution.released` 事件。
- `POST /evolution/experiments/{id}/rollback`：要求 approved_for_review 或 released。若本条是 released，选取 superseded_at 最新的一条 superseded 恢复为 released（restored_at / restored_by 指向触发回退的实验），本条置为 rolled_back，发出 `evolution.rolled_back {id, restored}`。
- `GET /evolution/release`：返回当前发布记录视图，无则 null。

所有状态变更在同一个 scope 事务内完成，替代与恢复不会出现两条 released 并存的中间态。

## 演练测试

`tests/test_evolution_release.py`（真实 PostgreSQL）：

1. `test_unattended_release_rollback_drill`：发布 A → 当前为 A；发布 B → A 变 superseded、当前为 B；回退 B → A 恢复为当前发布并带 restored_by；回退 A → 当前发布为空；重复回退返回 409。
2. `test_release_and_rollback_state_guards`：evaluated 状态 release/rollback 均 409；approved_for_review 可直接回退；rolled_back 后 release/approve 均 409。

全量测试：174 passed。
