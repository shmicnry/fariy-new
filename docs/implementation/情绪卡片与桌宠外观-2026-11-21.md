# 情绪卡片与桌宠外观（2026-11-21）

## 本次交付

### 1. 桌宠状态接口 `GET /v2/pet/state`

情绪由持久化信号确定性推导，每个状态都能追溯到具体事件（缘起原则），不做随机表演：

| 优先级 | 情绪 | 触发信号 |
| --- | --- | --- |
| 1 | waiting 等待确认 | 存在未过期、未决的站内审批 |
| 2 | busy 专注工作 | 存在 active 自主目标 |
| 3 | fulfilled 今日有成 | 今天完成过自主目标 |
| 4 | resting 预算休整 | 自主开启且当日分钟预算耗尽 |
| 5 | calm 平静待机 | 以上皆无 |

返回 `mood / label / reasons（中文缘起）/ signals（各计数）/ appearance（皮肤与模型地址）`。
信号全部来自数据库实时读取：审批按 `decision=None` 且 `expires_at` 未过期计数，目标按生命周期状态计数，预算复用自主模块的当日账本。

### 2. 外观配置（可插拔皮肤）

- `Config` 新增 `pet_skin`（`builtin | live2d | vrm`，默认 builtin）与 `pet_model_url`（≤2000 字符）。
- 校验：模型地址禁止控制字符；非空必须 `https://`；选择 live2d/vrm 必须同时提供模型地址（`model_validator`），否则 422。
- Live2D/VRM 模型文件由用户自备（版权与体积原因不内置）；未配置或加载失败时回退 builtin，`appearance.fallback` 恒为 `builtin`。

### 3. 管理后台（Web）

- 桌宠设置页新增皮肤下拉与模型地址输入，保存走完整配置 PUT。
- 新增「Fairy 当前状态」面板：展示情绪标签、缘起原因、信号计数与外观来源，数据来自 `/pet/state`。
- p3/p5/knowledge 页的配置保存全部携带 `pet_skin / pet_model_url`，避免整量 PUT 把外观重置；Service Worker 缓存升至 v26。

### 4. iOS 客户端配置回写缺陷修复

`FairyConfig` 此前缺少 `autonomy_topic_enabled / autonomy_topics / pet_skin / pet_model_url` 四个字段：
`setPetEnabled` 走「GET → 解码 → 整量 PUT」，解码时丢字段、编码时用默认值覆盖，导致在 iPhone 上开关桌宠会静默重置自主选题与外观配置。
本次补齐字段并用 `decodeIfPresent` 扩展兼容旧后端响应；新增编码往返测试锁定该回归。
