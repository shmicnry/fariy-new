# 网页来源版本刷新

日期：2026-11-19。本迭代增加网页来源的显式版本刷新，防止远端网页变化后继续把旧正文
当作当前证据。

## 行为

所有者可在来源复核记录中发起“检查并更新来源”。服务端会：

1. 重新通过现有 HTTPS、公网地址、DNS 固定和大小限制链路读取正文；
2. 计算新正文 SHA256 并与当前版本比较；
3. 内容未变化时只写入检查时间和摘要，不创建重复课程；
4. 内容变化时创建新来源、新课程和新的阅读任务；
5. 新来源标记为 `unreviewed`，必须重新人工复核；
6. 失效旧来源，以及引用旧来源的记忆、课程、测验、知识主张和其他派生记录；
7. 在 `source_refresh` 记录中保留旧 revision、旧摘要、新摘要、新旧来源 ID 和结果。

刷新读取失败或应用新版本失败时，当前来源保持有效，不把失败伪装成无变化。刷新请求
使用独立幂等键，重放不会再次访问网络。

## 接口

```text
POST /v2/learning/sources/{id}/refresh
{"revision": 1}
```

返回状态：

- `changed`：创建新版本并失效旧来源；
- `unchanged`：内容摘要一致；
- `failed`：读取或应用失败，旧来源继续可用。

## 安全与内容边界

- 只允许 `web_link` 来源；
- 仍拒绝 HTTP、本机、私网、非 443 端口、重定向、压缩正文和非文本媒体；
- 正文最多 256000 字符；
- 不执行 HTML 中的脚本或指令；
- 旧来源内容在失效时按现有遗忘语义清除，审计记录保留摘要而不永久保留旧正文副本；
- 新版本不会继承旧版本的“一手来源”等人工评级。

## 验证

- 内容变化：新来源版本号递增、旧来源、旧课程和旧记忆失效；
- 内容未变化：不创建新来源，状态为 `unchanged`；
- 网络失败：刷新记录为 `failed`，旧来源继续有效；
- 同一幂等键重放不重复抓取；
- PostgreSQL 16：**133 passed，0 skipped**；
- SQLite：**132 passed，1 skipped**，跳过专用 PostgreSQL 并发用例。

自动周期检查、来源白名单、跨版本差异摘要和抓取失败后的指数退避尚未启用；当前刷新
由所有者明确触发。
