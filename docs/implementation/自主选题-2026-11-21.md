# 自主选题（P5 补齐）— 2026-11-21

## 目标

在既有的「学习缺口 / 冲突核对」候选之外，增加所有者登记主题的自主选题通道：Fairy 可以围绕主人关心的主题主动提出学习候选，但仍在同一套预算、授权与验证边界内运行。

## 开关与门槛

- 新增配置项（`PUT /v2/config`，全量替换语义不变）：
  - `autonomy_topic_enabled`（默认 `false`）：主题候选总开关。
  - `autonomy_topics`（默认 `[]`，最多 20 条）：主题清单，每条 1–120 字符，去除首尾空白、剔除控制字符、去重。
- 生成主题候选需同时满足：
  1. `autonomy_enabled` 为真（自主性总开关，原有门槛）；
  2. `autonomy_topic_enabled` 为真；
  3. `source_allowed_hosts` 非空。允许域名为空时即使打开主题开关也不生成候选——主题学习必须有明确的来源边界，这是有意为之的更严格门槛（链接导入本身在允许域名为空时放行，主题通道不放行）。
- 每个主题预估 20 分钟，`origin` 为 `owner_topic`，成功条件固定为「在允许域名内导入来源并完成有原文依据的练习或主张，记录验证结果」。候选携带生成时刻的 `allowed_hosts` 快照，接受后原样写入目标（goal），后续改配置不影响已接受目标的边界记录。

## 生命周期与预算

- 候选与既有类型共用同一状态机：proposed → accepted / dismissed；接受时创建 planned 目标并预留分钟数。
- 接受门槛不变：`remaining_minutes ≥ estimated_minutes` 且 `remaining_items > 0`，否则 409 `autonomy_budget_exhausted`；自主性关闭时 409 `autonomy_disabled`。
- 修复既有缺陷：`accept()` 原先在事务内调用 `budget()` 新开只读会话，看不到未提交的新目标，返回的预算是陈旧值。现在 `budget(session=None)` 支持复用事务会话，接受响应中的预算即时反映刚预留的额度。独立 `GET /v2/autonomy/budget` 行为不变。
- 目标 start / pause / complete / cancel、按秒计费与超额暂停逻辑全部复用，未改动 worker：`run_cycle` 已在每轮调用 `refresh()`，主题候选随周期自动出现。

## 去重与「暂不处理」语义

- 去重键为 `topic:` + 主题原文。同一文本只生成一次候选，跨刷新周期不重复。
- 「暂不处理」（dismiss）对同一主题文本是**持久忽略**：后续刷新不会再推荐它。这与学习缺口、冲突候选的既有语义一致，避免 worker 每轮重新提出被驳回的主题。想重新学习同一方向，修改主题文本（如「海洋酸化」→「海洋酸化对珊瑚的影响」）即产生新候选。

## 管理界面（apps/web/p5.js）

- 「自主性与进化」页新增主题开关与主题文本域（每行一个主题），并注明需先在「知识与来源」配置允许域名。
- 候选卡片展示「允许来源域名」快照；队列标题与刷新按钮文案更新为覆盖主题候选。
- p3 / knowledge / app 三处配置保存入口均保留主题字段，避免全量替换时被抹掉。Service Worker 缓存版本 v24。

## 边界（明确不做）

- 不自动浏览网页、不自动抓取：主题研究仍通过所有者可见的允许域名链接导入完成，候选只是「提出计划」。
- 不接入云模型自动选题；主题完全来自所有者登记，模型不参与主题发明。
