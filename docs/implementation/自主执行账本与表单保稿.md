# 自主执行账本与表单保稿

日期：2026-11-18。本迭代把自主候选的“估算预算”升级为可监督的实际执行账本，
并修复后台事件自动刷新可能覆盖新输入的问题。

## 执行账本

接受自主候选后，系统会创建一个 `planned` 目标，并预留其预计分钟数。目标现在支持：

1. 所有者启动目标；
2. 暂停并保留已执行时间；
3. 从暂停状态继续；
4. 填写完成结果与验证依据后完成结算；
5. 取消目标并释放尚未使用的预留。

服务端按活动区间记录执行秒数。目标达到预留时长后，worker 会自动暂停并记录
`budget_exhausted`，防止目标继续占用无上限时间。完成或取消后，未使用的预留会释放，
已执行时间仍保留在当日账本。

每日账本使用 Mac 本地时区；也可用 `FAIRY_DAY_TIMEZONE` 指定 IANA 时区。降低每日
分钟上限时，如果新上限低于当前已预留和已执行时间，服务端返回 409，不会静默取消
仍在执行的目标。

新增 API：

```text
GET  /v2/autonomy/goals
POST /v2/autonomy/goals/{id}/start
POST /v2/autonomy/goals/{id}/pause
POST /v2/autonomy/goals/{id}/complete
POST /v2/autonomy/goals/{id}/cancel
```

所有状态变更都要求当前 revision，避免两个端同时操作时覆盖彼此。

## 管理端与原生端

- Web 自主页显示预留、已执行时间、目标状态、自动暂停原因与完成结果；
- 完成操作要求填写验证依据，不能一键宣称目标成功；
- SwiftUI 的“任务”和 Mac“自主”页面均可启动、暂停、继续、完成和取消目标；
- 原生取消目标使用明确的确认对话框；
- PWA 缓存版本提升为 `fairy-shell-v13`。

## 表单保稿竞态

后台 SSE 事件原先可能先安排 180 毫秒后的页面刷新。如果用户在这段时间内开始输入，
定时器仍会执行，导致新草稿被覆盖。现在定时器触发时会再次检查 `routeDirty` 和当前
焦点；存在草稿或编辑控件时只显示更新提示，不自动重绘。

真实浏览器验收同时验证：

- 接受候选后目标出现；
- 启动与暂停后 revision 和状态正确刷新；
- 完成请求携带填写的验证依据并返回 200；
- 完成结果在页面显示；
- 后台更新不会覆盖正在编辑的完成依据。

## 当前边界

账本负责监督自主任务的时间与状态，不等于已经具备无人值守研究、支付、Mac 键鼠操作
或自动发布能力。真实外部动作仍需 P2 来源白名单、P3 权限动作桥和 P5 独立构建/回滚。
