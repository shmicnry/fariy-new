# 设备配对与吊销（2026-11-21）

多端接入的第一步：主令牌只留在本机管理端，iPhone / iPad / 其他浏览器用可吊销的设备令牌接入。新增 `server/fairy/devices.py` 与「设备与连接」管理页，SSE 流对已吊销设备主动切断。全量测试 **166 passed**（新增 `tests/test_devices.py` 4 项）。

## 设计

- **配对**：管理端输入设备名称（1–64 字符），`POST /v2/devices` 生成 `fd_` 前缀令牌（`secrets.token_urlsafe(32)`）。明文令牌只在配对响应里出现一次；数据库与幂等缓存都只存 SHA-256 哈希。同一 Idempotency-Key 重放返回同一设备但 `token=null`，需要新令牌就换 key 重新配对。
- **鉴权分层**：`Authorization: Bearer <主令牌>` → `{"principal":"owner"}`；`Bearer fd_…` → 经 `compare_digest` 比对活跃设备哈希 → `{"principal":"device","device_id":…}`。配对、吊销接口仅限主令牌（设备令牌调用返回 403 `master_token_required`）；事件、流等读接口设备令牌可用。
- **吊销**：`POST /v2/devices/{id}/revoke` 幂等——首次置 `status="revoked"` 并 `revision+=1`、发 `device.revoked` 事件；重复吊销不再变更。吊销后该令牌立即 401。
- **SSE 切断**：`/v2/stream` 循环每轮先查 `devices.active(device_id)`，设备被吊销即推送 `event: device.revoked` 帧并结束响应。前端 `watchEvents` 收到该事件后停止重连并提示，避免已吊销设备无限重试。

## 管理页（apps/web）

- 侧边栏「系统」组新增「设备与连接」：已配对设备列表（名称 / 可用·已吊销 / 配对时间），吊销走确认按钮；配对表单生成令牌。
- 令牌用不可点 backdrop 关闭的对话框展示（`等宽 code 块 + 一键复制 + 「我已保存，关闭」`），页面刷新不会把仅显示一次的令牌冲掉。重放导致 `token=null` 时给出解释对话框。
- 事件通知路由 `device.*` → 「设备连接已更新」，可跳设备页或总览。Service Worker 缓存版本升到 v23。

## 验证（tests/test_devices.py，4 项）

1. 令牌只出现一次：配对返回 `fd_` 令牌；重放同 key 同 id 且 `token=null`；列表与数据库 Record、幂等 Request 表均无明文、只有哈希。
2. 名称校验：空白 / 空串 / 65 字符 → 422，不落库。
3. 权限边界与吊销：设备令牌可读事件、配对/吊销 403；吊销幂等（revision 不变）；吊销后与伪造 `fd_` 令牌均 401；主令牌不受影响。
4. SSE 切断：直接驱动 ASGI 应用收集 send 消息（`httpx.ASGITransport` 会缓冲整个响应，无法测永不结束的 SSE），收到首帧后经服务层吊销，流在 10 秒护栏内自行结束且包含 `event: device.revoked`；随后设备令牌 401。

全量：`FAIRY_TEST_POSTGRES_URL=… pytest tests -q` → **166 passed**。

## 边界

- 设备令牌当前与主令牌共享读权限（事件、记忆等），写操作里仅配对/吊销做了主令牌限制；后续按端细化写权限时在此鉴权层扩展。
- 真机 iPhone 接入仍需用户侧签名与安装（见工作事项盘点），本阶段交付的是令牌与通道本身。
