# P3–P5 可运行纵切交付与验证

日期：2026-11-17。工程版本：0.3.0。

本轮把 P3–P5 从设计页推进为可操作的纵切。这里“完成”指本文列出的本地功能已经实现并通过自动/浏览器/编译验证；“完整 P3–P5 愿景”中的真实 TCC、语音视频、推送、自动公网选题和发布仍需另行提供设备权限与外部服务，不能由本轮代码替代。

## P3：技能与 Mac

### 技能生命周期

六个内置技能已注册到技能中心：

- Mac 只读状态；
- Mac 只读 Accessibility Tree；
- 启动允许列表应用；
- 学习资料检索；
- 世界主张查询；
- 自主候选查询。

安装、授权、启用和执行分开。安装本身不授予权限；授权带时限和明确 permission；停用立即撤销有效授权。任意脚本、依赖安装和路径穿透包没有执行入口。习得知识仍单列，不能自动变成可执行技能。

调用结果会稳定保存为 `completed` 或 `failed`；失败包含脱敏错误码和
`skill.invocation_failed` 事件。Mac 子进程执行位于工作线程，不阻塞 SSE 或其他 API
请求。

### Mac 桥

新增真实的只读系统能力：

- 系统平台、macOS 版本与执行模式；
- 应用名称与路径；
- 允许目录内文件/目录元数据；
- realpath 检查与符号链接越界拒绝；
- TCC 状态明确显示 `unknown_not_probed`。

唯一新增写入动作是启动允许列表中的应用。它要求 `mac_execute`、应用允许列表、技能授权和所有者点击四层同时满足，只执行固定参数 `/usr/bin/open -a` 或 `-b`，不拼接 shell。成功只表示启动命令成功，窗口与任务结果仍未验证。

仍未实现：键盘/鼠标注入、AX 树自动操作、屏幕录制、窗口内容读取、文件写入和跨执行面对账。这些能力在系统 TCC 授权与独立桥测试前保持关闭。

## P4：Mac 与 iPhone 体验

### 管理端 PWA

- 管理端采用 macOS 式侧栏、半透明材质、紧凑信息密度和窗口红黄绿状态标识。
- 手机宽度切换为大标题、44pt 最小触控区域、底部五项标签栏、系统安全区与毛玻璃底栏。
- 卡片使用入页、按钮按压和焦点环动画，并适配 `prefers-reduced-motion`。
- 支持浅色/深色模式、PWA manifest、Service Worker、离线应用外壳和 192/512/Apple Touch 图标。
- Service Worker 不缓存 `/v2/` 私密 API 响应，只缓存静态应用壳。
- 对话页使用浏览器 Web Speech API 提供可编辑语音输入与回复朗读；浏览器不支持时明确禁用。浏览器语音识别可能由系统/浏览器供应商处理音频，这条链路不经过 Fairy 云模型，但不能宣传为本地 ASR。
- macOS `/usr/bin/say` 提供本地 WAV 朗读；设置 `FAIRY_WHISPER_CLI` 与 `FAIRY_WHISPER_MODEL` 后，同一页面优先使用本地 Whisper 转写，失败前不把音频持久化。

### SwiftUI 原生骨架

新增 `apps/ios/FairyApp` Swift Package：

- macOS 使用 `NavigationSplitView` 侧栏；
- iPhone 使用底部 `TabView`；
- 对话、记忆、课程、待确认任务、自主候选、技能和设置读取真实 API；
- 原生端可纠正/遗忘记忆、提交课程评定、批准/拒绝站内操作、安装/启用/停用技能并接受/忽略自主候选；
- 所有者令牌保存到 macOS/iOS Keychain，服务地址保存在本机偏好设置，应用重启后自动尝试恢复连接；
- 对话输入、加载状态、消息滚动和连接 Sheet 使用 SwiftUI 动画。
- 设置页可请求设备本地通知；前台每 8 秒同步一次状态，对话回答可使用 `AVSpeechSynthesizer` 在本机朗读。
- 原生请求等待窗口覆盖本地与云副模型的完整路由时间；课程人工验证要求有效原文依据。

验证：

两个平台均编译通过。尚缺 Xcode App target、签名、真机 Keychain/TCC、APNs 推送、麦克风语音识别、视频通话和 App Store 发布材料。原生 TTS 已使用系统语音合成。

## P5：自主候选、预算与进化实验

### 自主候选与硬预算

worker 可以从“最近练习未通过”和来自不同来源的世界知识冲突产生候选。每个候选包含原因、待解决问题、来源、预计分钟数和去重键；同一次刷新与后续刷新都不会重复入队。

- 自主功能默认关闭。
- 启用后分别限制每日分钟数和候选数。
- 接受候选才生成 `planned` 目标，并从当日预算扣减。
- 预算不足返回 409，不静默超额。
- 用户输入不因后台候选被阻塞。

当前候选来自本地已有缺口，不自动联网搜索。浏览外部资料仍需 P2 的来源采集与用户配置。

### 隔离进化实验

新增固定用例实验台：

- 所有者提供固定测试用例、基准候选和一个或多个候选输出；
- 服务端使用不可变规则检查 required/forbidden terms；
- 同一幂等键不会重复评测；
- 结果保存每个用例的得分与原因、基准分数、推荐候选；
- 候选与基准同分时始终保留基准，即使候选在输入中排在前面；
- 人工可记录“待评审”，也可回退实验；
- `runtime_changed=false` 和 `scoring_immutable=true` 始终写入结果。
- 管理端保存自主预算不会覆盖 `mac_execute` 与设备允许范围。

这是隔离评测组件，不是自动修改代码或发布模型。真正的灰度发布需要在独立构建、权限测试、留出集与回滚系统中完成。

## 仍需外部条件

1. 真实 Mac 应用任务需要辅助功能/屏幕录制授权和经过审计的 AX/ScreenCaptureKit 桥。
2. iPhone 局域网连接需要 HTTPS/可信私有网络、设备配对与撤销；默认服务仍只绑定回环地址。
3. 本地 TTS 与 macOS Vision OCR 已可用；Whisper 本地 ASR 需要用户提供模型，视频与 APNs 仍需要供应商、设备凭据和真机验收。
4. 自动公网选题需要受控浏览器/抓取器、来源白名单、网络预算和失败退避。
5. 自动进化发布需要独立构建产物、隔离评分器、灰度指标与自动回滚。
